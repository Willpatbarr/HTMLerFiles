Decisions, Verify & TODO

Seven judgement calls, each with what I rejected

1 · Fixed the method bug rather than asserting the old behaviour

The test failed. Returning HTML 200 for POST /anything is wrong, not merely surprising.

Rejected

Change the test to document current behaviour. A write that appears to succeed is the worst kind of harmless — nothing errors, and nothing happened.

2 · Put the guard on the static handler, not per-route

It is a property of serving files, so it lives with the file server.

Rejected

Register every route for all methods. POST /healthz returning {"status":"ok"} would imply POST is supported.

3 · Created LAM-39 rather than folding fixes into an existing ticket

Rejected

Amend LAM-29. Those tickets are Done, and an audit finding deserves its own record so the history stays readable.

4 · Branched off LAM-29-B

Why not the epic branch

It lacks LAM-28 and LAM-29 entirely, because those PRs never merged.

5 · Substring-matched the banned dependencies

Rejected

Exact names only — pg-promise would slip straight through.

6 · One ADR covering all of LAM-29's decisions

Rejected

One ADR per decision. They are one coherent packaging choice; splitting them would obscure that the shell-less base is why the operator binaries ship.
