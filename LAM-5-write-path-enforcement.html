LAM-5 — Write-Path Enforcement

Decide and document how the JSON blob and the search index are kept in sync · Project E-LAM-0001 · Branch LAM-5-B

One-Sentence Version

LAM-3 already built most of the encapsulation but never ratified it — so this ticket writes the decision down, collapses two index-write loops into one, and adds an AST test that fails the build if any other package touches those tables.

Must Know

Code structure, backed by a mechanical check

Not test-and-review discipline alone. Four mechanisms, in order of strength:

Mechanism 1

Unexported pool. Service.pool is private, so no caller can reach through a Service to the database.

Mechanism 2

One exported write method. Save is the only way in from outside the package.

Mechanism 3

One index-write site. A new unexported indexBody becomes the only INSERT INTO search_index in the codebase.

Mechanism 4

AST boundary test. Fails the build if any package outside internal/document issues SQL against either table.

Two naming calls worth recording

  • Keep Save, not SaveDocument. The ticket suggests the latter, but document.SaveDocument stutters — against the Effective Go guidance the ticket itself links.
  • Unexport FieldText → fieldText. It is derivation internals, not API. Nothing outside the package calls it.
Must Know

Why the existing claim isn't true yet

The package comment already asserts "Service.Save is the only code path permitted to write either table." Three things make that unenforced or inaccurate.

Gap 1 — the hole structure can't close

Go's encapsulation is package-scoped. Any package can call db.Connect and issue raw SQL against document / search_index. main.go already holds a bare *pgxpool.Pool.

Structure makes the right path easy — not the wrong path impossible. That is what the AST test is for.

Gap 2 — one write site is actually two

Save and RebuildIndex each carry their own INSERT INTO search_index loop. Two loops is two places to drift.

Gap 3 — an unlabelled exception

RebuildIndex writes the index without touching a blob. That is legitimate — it is a pure function of the blobs — but right now it reads like a violation. The ADR has to name it as sanctioned.

Important

Where this came from

The hybrid storage model (LAM-3) keeps two representations of a document: the document.body JSON blob as source of truth, and the derived search_index rows.

§4 of the Architecture & Tech Stack notes flagged the obvious risk — a write path that updates one and not the other — and deferred the design to its own conversation. This is that conversation.

// indexBody writes one document's search_index rows from its decoded body. It
// is the only place in the codebase that inserts into search_index - Save and
// RebuildIndex both route through here so the two paths cannot drift.
//
// It takes a pgx.Tx rather than the pool on purpose: an index write that is not
// already inside the caller's transaction is exactly the drift this design
// exists to prevent, so the signature makes that impossible to express.
func indexBody(ctx context.Context, tx pgx.Tx, docID string, body map[string]any) error {
	for fieldID, value := range body {
		if _, err := tx.Exec(ctx,
			`INSERT INTO search_index (document_id, field_id, content)
			 VALUES ($1::uuid, $2, $3)`,
			docID, fieldID, fieldText(value),
		); err != nil {
			return fmt.Errorf("index field %q: %w", fieldID, err)
		}
	}
	return nil
}

// tableSQL matches a SQL statement naming either table this package owns.
var tableSQL = regexp.MustCompile(
	`(?i)\b(insert\s+into|update|delete\s+from|from|join)\s+"?(document|search_index)\b`)

// TestNoSQLOutsideThisPackage fails if any package other than this one issues
// SQL against document or search_index.
//
// Go's encapsulation is package-scoped: Service.pool being unexported stops a
// caller reaching through a Service, but nothing stops a new package calling
// db.Connect and writing the tables itself. That is the hole this closes.
//
// Only string literals are inspected, and files are parsed with comments
// discarded, so prose mentioning a table name is never a failure.
func TestNoSQLOutsideThisPackage(t *testing.T) {
	root := filepath.Join("..", "..")
	fset := token.NewFileSet()
	var offenders []string

	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if d.IsDir() {
			if d.Name() == ".git" || filepath.Base(path) == "document" {
				return fs.SkipDir
			}
			return nil
		}
		if filepath.Ext(path) != ".go" {
			return nil
		}

		// Mode 0 drops comments, so only real string literals are inspected.
		f, err := parser.ParseFile(fset, path, nil, 0)
		if err != nil {
			return fmt.Errorf("parse %s: %w", path, err)
		}

		ast.Inspect(f, func(n ast.Node) bool {
			lit, ok := n.(*ast.BasicLit)
			if !ok || lit.Kind != token.STRING {
				return true
			}
			s, err := strconv.Unquote(lit.Value)
			if err != nil {
				return true
			}
			if tableSQL.MatchString(s) {
				offenders = append(offenders, fset.Position(lit.Pos()).String())
			}
			return true
		})
		return nil
	})
	if err != nil {
		t.Fatalf("walk: %v", err)
	}

	for _, o := range offenders {
		t.Errorf("SQL against document/search_index outside package document: %s\n"+
			"  route it through document.Service so the blob and the index stay in sync\n"+
			"  see docs/adr/0001-write-path-enforcement.md", o)
	}
}
