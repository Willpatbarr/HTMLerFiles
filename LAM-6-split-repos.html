LAM-6 — Split Into Separate Frontend and Backend Repos

E-LAM-0002 · first ticket · LaminarFlow-Frontend + LaminarFlow-Backend

One-sentence version

Finish the two-repo split by writing the frontend's README, retitling the backend's, and pointing the CI ref at main instead of a per-epic branch pin.

The ticket was out of date — now corrected

The status note pinned to LAM-6 was dated 2026-09-01 and predated both LAM-38 and LAM-29, so it claimed CI was missing from both repos. It is not.

The E-LAM-0002 audit on 2026-09-05 rewrote that note. The ticket now matches what is below.

LAM-6 asks for three things. Two are already done:

Precondition — do this first

Land E-LAM-0001-B and E-LAM-0001-F on main in their repos. Every step below assumes main carries the real work: Step 1 cuts the E-LAM-0002 branches from it, and Step 5 points the image build at it.

What is actually left

  • Neither README links the other repo. Both state their role already — the backend's since LAM-4, the frontend's since LAM-28 rewrote it. The cross-link is the half of ticket step 3 that is actually outstanding.
  • The frontend README still carries three Vite template sections inherited from the scaffold.
  • The backend README never says which half of the split it is.
  • FRONTEND_REF in the backend's CI pins E-LAM-0001-F. Once E-LAM-0001 lands on main, this becomes main and stops rotting per-epic.

Must know

  • Step 2 — the frontend README is the actual deliverable of this ticket.
  • Step 5 — a stale FRONTEND_REF lets a broken bundle pass CI silently.
  • Precondition — E-LAM-0001 must be on main before Step 1 or Step 5 run.

Important

  • Step 1 — epic branches cut from E-LAM-0001-*, never from main.
  • Step 4 — one edit, but it is what closes ticket step 3 on the backend side.
  • Step 6.1 — run the frontend checks before publishing a README that documents them.

Optional

  • Step 3 — deleting readme.txt is hygiene, not a requirement.
  • Step 6.3 — watching the run; the notification works just as well.

Flagged rather than fixed — each of these is a real observation that this ticket deliberately does not act on.

The backend image job checks out the frontend repo, on every commit

The check job is already independent — scripts/test.sh never touches the frontend. The coupling is in the workflow's trigger, not the architecture.

LAM-41 moves the image build to tags and workflow_dispatch, and turns FRONTEND_REF into a dispatch input. ADR-2 is unaffected.

No folder-structure section in the frontend README

LAM-9 owns the feature-based scaffold. Documenting it now would describe files that do not exist yet — including the router it needs and does not yet have.

No test script in the frontend

npm run lint is the only gate today. LAM-40 was filed on 2026-09-05 to add Vitest, a test script, and the CI step.

Step 2.3 writes the README's check list without npm test for that reason — LAM-40 adds the line.
