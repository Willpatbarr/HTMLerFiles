Why the change was needed

The screen is the only collector. Opening the file picker drops it, so WhileSubscribed stopped the flow and re-seeded it to Loading. A save that wrote the file correctly then reported failure.

What the change does

Keeps the flow alive for the life of the view model, so the rendered code is still there when the picker returns and nothing re-encodes on the way back.

After

kotlin
private fun save(documentUri: Uri) {
    viewModelScope.launch {
        val loaded = uiState.statusFlow
            .first { it != EventQrStatus.Loading } as? EventQrStatus.Loaded
        if (loaded == null) {
            showSnackbar(R.string.calendar_event_qr_save_failed)
            return@launch
        }
        val saved = saveQrCodeToDocumentUseCase(loaded.bitmap, documentUri)
        ...
    }
}
Why the change was needed

The picker is a separate app, so a low-memory device can kill this one while it is open. The result then reaches a brand-new view model whose code has not finished re-encoding, and the user is left the empty file the picker already created.

What the change does

Waits for the state to resolve instead of sampling it once. Nothing is stored: the code is rebuilt from the event's link, which is a local database row the restarted app reads back.

Note

This gap was present in every earlier version of the branch too. The change closes it rather than preserving it.

Why the change was needed

The picker launched from inside the hoisted composable, so a test could not observe the Save tap. Save was the one app-bar action with no click test, and three separate mutations of it passed the whole suite.

What the change does

Moves the launcher up to the wrapper that owns the view model, so the internal composable is fully drivable and a spy lambda can assert which file name reaches the picker.

Why the change was needed

The first version of this test ran in 8 ms against a 5,000 ms stop timeout and never re-subscribed, so the flow never actually stopped. Reverting Lazily to WhileSubscribed left all 39 QR tests green.

What the change does

Drives a virtual clock past the timeout and re-subscribes, which is what makes the upstream restart. The encode count is the assertion that discriminates, because the state keeps its last value either way.

Verified

Both new guards were run against the code they describe. Reverting Lazily fails this test on the encode count; reverting the awaited save fails the process-death test. Two other guards were restored in the same pass: the snackbar flow pass-through, and the encoder's 512 px default asserted as a literal.
