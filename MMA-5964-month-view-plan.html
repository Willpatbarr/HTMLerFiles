1Dynamic 4–6 week grid — size to the month, no padding weeksMust Know

FR-27 · ticket AC #3

Today the grid is fixed: WEEKS_SHOWN = 6 (month/CalendarMonthView.kt:61), and dates is built as WEEKS_SHOWN * DAYS_IN_WEEK days from gridStart (L132). A month like Feb-non-leap starting on the first day of week fits in 4 rows, most months in 5, and only some in 6 — so a fixed 6 always risks a trailing all-other-month padding week. The spec calls this out as a change from the prototype.

  • Compute rows from the data: gridStart = startOfWeek(month.firstDay, locale) (WS2) through the week containing month.lastDay. Weeks = ceil((daysFromGridStartToLastDay + 1) / 7) → yields 4, 5, or 6.
  • Replace the fixed (0 until WEEKS_SHOWN * DAYS_IN_WEEK) range with that computed count; the chunked(DAYS_IN_WEEK) row loop stays as-is.
  • Cells keep Modifier.weight(1f) vertically, so 4-row months get taller cells automatically — sanity-check heightIn(min = 72.dp) still looks right at 4 rows.
  • Interacts with WS2: the row count depends on the locale week-start, so land WS2 first (or together).

3Cell ordering — multi-day first, then by start timeMust Know

FR-12 · AC-10

Two parts: ordering and how many chips show. Order each day's events multi-day-first then by start time, in the cell (Month-local, not the shared mapEventsToGrid — the time-grid views depend on its order). The chip count is height-driven: the cell shows as many chips as fit and reserves the last line for "N more" on overflow, so it never clips. Spec divergence: the original spec said "≤3 chips" — amended to "as many as fit" (FR-12) because a fixed 3 left large-screen cells with a lot of empty space.

  • Sort each day's list before capping to what fits: sortedWith(compareByDescending<CalendarGridEvent> { it.multiDay }.thenBy { it.startTime }). Each event already carries multiDay and startTime.
  • Do it Month-local (in the cell / a Month helper), not in the shared mapEventsToGrid — the grid views route multi-day events into the all-day row and rely on the existing order; re-sorting the shared map could shift Day/Week/3-Day. This is the key watch-out.
  • "N more" count is unaffected — it's events.size - shown.size regardless of order.
