Step 1.2 — Map the new fields

Must Know
Use case stops discarding public fields.
…/calendar/detail/GetEventDetailsUiStateUseCase.kt
  • isPublic maps straight through
  • photoUrl = photoPath when public, blank→null
  • audienceText: parse with enumValueOfOrNull<EventAudience>() (drop unknowns), format each as "Group - Audience" via AudienceGroup, EVERYONE bare, resolve labels via injected stringResources, join with the bullet, null when not public
  • Neither the bullet nor the dash is a Kotlin constant — both come from string resources; see the separator note below
  • webLinkUrl = link when public, else null
  • TODO(Q4) comment marks the single flip point for the gate

Reuse: both EventAudience.labelRes and AudienceGroup from the edit package (EventAudienceLabels.kt, same module) — AudienceGroup.audiences gives the reverse lookup for the prefix. No new constructor params, so Koin wiring is untouched.

Separators are localized resources, not constants. MMA-6004 set this pattern in RecurrenceSummaryFormatter: the resource holds the bare glyph and the code adds the surrounding spaces. Commit 1 therefore touches strings.xml — the rest of the string work still waits for Commit 2.

  • calendar_recurrence_summary_separator is renamed to calendar_event_list_separator ("•") and now serves both the recurrence summary and the audience row. Update the RecurrenceSummaryFormatter call site and the stub in RecurrenceSummaryFormatterTest — the test stubs resources by id and fails loudly if you miss it
  • New calendar_event_audience_group = "%1$s - %2$s" for the "Adults - Women" join. A two-placeholder format string, not a dash separator — that is how this repo joins two values (calling_hyphen, country_currency, sex_age_hyphen are all this shape), and it lets a locale reorder the pair instead of hardcoding group-then-audience in Kotlin. feature/calendar/strings.xml declares no xliff:g namespace, so use plain %1$s, not core's xliff style
  • Rename now rather than later: feature/calendar has no values-* locale dirs yet, so there are no translations to churn. That window closes once translation lands

There is no EventAudience.fromString. The enum is maltSync's and audiences round-trip as plain enum names (EventCreateInput writes it.name), so parse with enumValueOfOrNull<EventAudience>() from org.ics.mobile.commons.ext — the same helper CalendarEnumConverters uses on these exact strings, and libs.church.mobile.commons is already a direct :feature:calendar dependency. Server order is worth keeping as-is: the write side already canonicalizes it.
