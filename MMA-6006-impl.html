│ Step 3 — Calendar Eligibility List (cut — reference only)

Cut from the plan — kept here for reference

Built, then reverted. Commit 3acad11ae3 is out of the branch; recover it with git cherry-pick 3acad11ae3 or from the saved step3-calendar-eligibility.patch.

Why it went: nothing consumes it. Its only consumer is MMA-5952's recipient picker, which has no code, no branch and no PR, and is itself waiting on MTMS-151 — Blocked, pending server changes, no date. MMA-6006 scopes this out explicitly too.

What it would have closed

No shared-library work would have been needed

The shared-library work that is outstanding (the missing enum, the display-name source) is tracked on MTMS-151 and blocked neither this nor Step 2. See Close Out → Contract Gap.

Schema v9 is still in flux

CalendarDatabase.version = 9 and CalendarMigration9.kt are committed, but schemas/…/9.json is untracked — so v9 is not finalized. Amend the existing migration; no v10 bump. Leave 9.json untracked.

Where a chip label actually comes from

The use case maps over lane 1's list, not lane 2's map, so the chip order and count come from the event. Lane 2 only supplies labels: names[type] ?: type.toTitleCase(). Three cases collapse into that fallback — the type is absent from the map, its stored name is blank, or the lookup was skipped because the tab is not showing.
