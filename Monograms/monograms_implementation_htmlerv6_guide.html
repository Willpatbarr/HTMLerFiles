Monograms Implementation

When a member has no photo, we show their initials in a circle (a "monogram") instead of the generic silhouette. The first two screens are live — this plan finishes wiring it into every remaining screen that renders a person photo.

One sentence

The monogram field already exists end-to-end in the data layer; finishing the feature is mostly threading that one field from each screen's DAO query through to its PersonPhoto call.

General Steps

The repeatable recipe for wiring a monogram into one screen. Every screen follows the same path: select the column, add the field to each model in the chain, then render it.

Goal

Thread monogram from the database column → DAO query → repo/domain model → UI state model → the screen's PersonPhoto call.

The 6-step recipe Must know

Steps 1–5 are the threading work; step 6 is verification. Most screens are a handful of one-line edits.

1

Select the column in the DAO query

The monogram column already exists on the Individual table (Migration 47). Add it to the query's SELECT columns for that screen.

// e.g. MinisteringDistrictDao / IndividualDao column list
i.monogram          // raw query
individual.monogram // column-constant style (DISPLAY_CALLING_INDIVIDUAL_COLUMNS)
2

Add monogram to the repo / domain model

Add val monogram: String? to the data class that carries the person's display info (e.g. MinisteringSupervisor, DisplayCallingIndividual). Models that map directly from Individual/IndividualEntity already expose it for free.

3

Add monogram to the UI state model

Add val monogram: String? to the screen's UI model (e.g. DistrictSupervisor) so the composable can read it.

4

Thread it through the UseCase / mapper

In the Get*UiStateUseCase (or mapper) that builds the UI model, pass monogram = source.monogram.

5

Render it in the composable

Two valid patterns exist — both shipped as references. Prefer passing the param into PersonPhoto unless you specifically want to skip the photo load.

Pattern A Preferred

Pass monogram into the existing PersonPhoto; it falls back to the monogram when the photo is unavailable. Used by Organization.

PersonPhoto(
    photoUriFlow = item.photoUriFlow,
    contentDescription = null,
    modifier = Modifier.size(40.dp),
    monogram = item.monogram,
)
Pattern B Explicit

Show the monogram immediately without attempting a photo load. Used by Ministering Organization.

if (!item.monogram.isNullOrBlank()) {
    MonogramPhoto(monogram = item.monogram, ...)
} else {
    PersonPhoto(photoUriFlow = ..., ...)
}
6

Build & verify

Run the screen and confirm members without a photo show their initials. Add the DB column to the DAO test fixtures if that query is covered. Then check the screen off in the Notion tracker.
