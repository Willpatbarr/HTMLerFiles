The pull request is the item, so the link cannot be forgotten

Every external tool considered here links a ticket to a pull request by reading an identifier out of the branch name or the PR body. Miss the identifier and the tool silently does nothing.

GitHub Projects has no identifier to miss. The pull request is the item. With 27 juniors and a branch convention that two merged PRs have already broken, that is worth more than it looks.

There is no built-in PR opened → In Review

The built-in automations are a fixed short list: auto-add items matching a filter, auto-archive, set Status to Done when an item closes, and set Status to Done when a pull request merges. The last two are on by default.

There is no trigger for opened, ready for review or approved. Moving an item to In Review on PR open needs a hand-written Actions workflow calling the GraphQL API. It is an open request on GitHub's own community discussions, not a setting.
