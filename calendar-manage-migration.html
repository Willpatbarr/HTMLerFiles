Calendar Manage Migration

Branch MMA-5973  ·  two commits  ·  pure relocation, no behavior change  ·  all work is in-repo, no external dependency

One-Sentence Version

Move the Manage Calendars screen into :feature:calendar and CalendarRepository into :repo:calendar, bridging the two dependencies that would otherwise point backwards into app with a pair of narrow interfaces.

Why Must know

CalendarRepository is the blocker for the whole calendar modularization. It still lives in app, and every calendar UI use case injects it — so no calendar UI can leave app until it moves.

  • Already extracted: :database:calendar is complete. :feature:calendar owns grid, month, week, day, schedule, the event editor, and location.
  • Still stranded in app: Manage Calendars (screen + UiState + ViewModel + use case + color picker) and the read/agenda repository beneath it.
  • Deliberately staying in app: CalendarSyncRepository and CalendarSyncWorker, because they are woven into the sync2 pipeline (ToolsPersister, RemoveDataUseCase, SyncRepository).
  • Scope discipline: the grid, schedule, event-detail, and sample-seeder code stays in app this round. It only gets import updates.

Verification Must know

Gate each commit separately

Long builds exceed the tool timeout, so log to a file and poll rather than trusting a single foreground exit code.

./gradlew :app:testDebugUnitTest --tests '*KoinTest*' \
          :app:testDebugUnitTest --tests '*Konsist*' \
          :repo:calendar:testDebugUnitTest \
          :feature:calendar:testDebugUnitTest > build.log 2>&1 &

./gradlew assembleDebug detektDebug :app:projectHealth > build.log 2>&1 &

KoinTest is the sharpest tool here: Module.verify() catches an unbound constructor param, allowOverride(false) catches a stale duplicate, and the Konsist sweeps catch an unregistered ViewModel or a package/path mismatch.

Gotchas Important

  • Atomic Koin edits. The single most likely way to break the build. Six definitions, each needing add and remove in one commit.
  • Konsist package-matches-path. Files must land at exactly the paths listed, or the architecture test fails.
  • Do not add @PreviewTest to ManageCalendarsPreview or CalendarColorSelectionPreview. The screenshot plugin only renders annotated previews in src/screenshotTest, so moving them into src/main generates and requires no reference images.
  • Recompile after any lint or format auto-fix. An auto-fix can break compilation even when the prior build was green.
  • Ordering nuance. After Commit A, GetManageCalendarsUiStateUseCase is still in app and imports from :repo:calendar. That is fine — app already depends on it. Fix those imports in A, move the file in B.

Follow-up — explicitly out of scope Optional

To delete the app-implements-repo inversion later, replace CalendarRefreshScheduler with the dominant convention.

  • CalendarSyncWorkScheduler : AppWorkScheduler2 plus Impl in :repo:calendar, mirroring GroupWorkScheduler and the module's own CalendarEventWorkScheduler.
  • Move CalendarSyncWorker there; delete refreshCalendar from the 629-line WorkScheduler; add implementation(project(":repo:work")).
  • Payoff: collapses WorkScheduler + SyncMode into one injected dependency for CalendarViewModel and the grid/schedule use cases.
  • Cost: the worker's fully-qualified name changes, so already-enqueued work from a prior install fails to instantiate once on upgrade. Benign — it is non-retrying and re-enqueued on the next refresh — but worth a PR note.
