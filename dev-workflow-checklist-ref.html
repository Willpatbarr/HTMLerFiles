Ticket Workflow Checklist

Five phases, a triage table for failures that are not yours, and a weekly sweep. Every item here cost something once.

flow
/kickoff  →  worktree  →  verified slices  →  device pass  →  /preflight  →  PR  →  close the worktree

Phase 0 — before touching code

│Setup

Skipping this is what produces a red gate nobody can attribute.

  • gh auth status — active account is willbarr_church Check, never switch blind. Acting on the memory without checking once had a correctly-pushed branch about to be deleted.
  • Worktree lives outside the repo ~/.claude-worktrees/MemberTools-Android/<branch> — an in-repo tree made Konsist scan 10,347 files and the gate took 17m29s.
  • Branch off current upstream/main Not a stale local main; the maltSync pin moves upstream without you.
  • Android Studio sync and your own Gradle runs are idle Two builds in one checkout corrupt each other's build/.
  • Older branch of mine still unpushed? Finish it or park it on purpose Twelve worktrees exist right now; several hold green work nobody is waiting on because nobody knows it is done.
bash
gh auth status
git worktree add ~/.claude-worktrees/MemberTools-Android/MMA-XXXX -b MMA-XXXX upstream/main
pgrep -fl GradleDaemon   # must be quiet before a background gate

Phase 1 — plan before code

│Plan

Tickets planned this way did not get re-scoped mid-build. MMA-5878 was re-scoped after the first plan and the whole plan was reverted.

  • /kickoff <MMA-XXXX> — plan doc, no code
  • Walk the FRs with /rubberDuckey, one at a time
  • Open questions get asked, not designed around A question answered in the plan doc costs a paragraph; answered in code it costs the branch.
  • Plan doc saved under ~/Documents/TicketPlans/<TICKET>/ and actually opened

Phase 2 — build loop, one slice at a time

│Build

A long autonomous run is what produces a diff you cannot review and commits you did not ask for.

  • One slice, then pause at the next real fork
  • Inner gate on the changed module only
  • New Robolectric test carries @Config(sdk = [34]) Paired with @RunWith(AndroidJUnit4::class) as one unit; without it the test dies configuring, not asserting.
  • Comment density matches the sibling file Class KDoc for constraints, nothing on self-evident properties, no FR or AC ids in code.
  • Leave it uncommitted until I have read the diff myself
bash
./verify.sh --module :feature:calendar --inner
./verify.sh --module :feature:calendar --full   # mid-work checkpoint

Phase 3 — device pass

│Device

MMA-5917, 5903, 5928, 6010, 5964, 6040 all reached "green, uncommitted, pending device pass" and stopped there.

  • VPN up before the emulator cold-boots Dev mode breaking is stale cached DNS; reconnecting the VPN while the emulator runs does not take.
  • Exercise every state the diff touches, not the happy path
  • Moved or renamed composables get a runtime click-through Unit tests cannot see a moved @Composable regression.
  • Screenshot or recording captured for the PR body
Stop rule A ticket without a device pass is not "done pending review" — it is unfinished. Park it with a note or finish it; do not start the next ticket on top of it.

Phase 4 — preflight and PR

│Preflight and PR

In-flux schema JSON and the maltSync pin are the two things that keep leaking into diffs.

  • /preflight — add --thorough for a wide diff, --iso <TestClass> for a flow test
  • Diff against upstream carries no gradle/libs.versions.toml and no stray files
  • Schema JSON for an in-flux version stays untracked Untracked right now: MemberDatabase 49, CalendarDatabase 9, MapDatabase 2.
  • PR opened against upstream with an explicit head
  • Worktree removed, or parked with a note saying why
bash
git diff upstream/main..HEAD --stat
git push -u origin <branch>
gh pr create --repo ICS-Eng/MemberTools-Android \
  --base main --head willbarr_church:<branch> --title "MMA-XXXX ..."

Never unasked

│Git history

Commit, push, stage, rebase, amend. Work stays visible in git status so the diff is reviewable where you left it.

│The spec folder

feature/calendar/spec/ belongs to someone else. New spec content goes in the Jira ticket or your own docs.

│The maltSync pin

Bumped by the release owner. After a rebase, confirm the moved pin reads as upstream's and not as a stray change in your PR.

│In-flux schema JSON

A schema version still being edited stays untracked until that version is locked.

Weekly sweep — ten minutes

│Sweep

Twelve worktrees, several with unpushed green work, is the state this exists to catch.

  • git worktree list — remove anything shipped or dead
  • Each survivor: pushed, PR open, or a park note written
  • /preflight update <PR #> on any PR that came back with review comments The rule store is how a reviewer's comment stops recurring; it has 49 rules and the top offenders repeat 4 to 7 times.
bash
git worktree list
git worktree remove ~/.claude-worktrees/MemberTools-Android/<done>
