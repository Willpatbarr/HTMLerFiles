The problem

A browser cannot load a modern JavaScript app the way you wrote it. Source is split across hundreds of files, imports things by bare name, and often is not JavaScript at all. Something has to turn all of that into files a browser will accept.

The traditional answer bundles the whole app up front. Bundling up front is fine once, but bundling happens on every dev server start and, in part, on every save — so the wait grows with the size of the codebase, exactly as the codebase becomes worth working on.

What Vite does

Vite's move is to stop treating the app as one thing. Dependencies and your own source have opposite characteristics, so they get opposite treatment.

DependenciesYour source
How often it changesalmost neverconstantly
How much there isa great dealcomparatively little
What Vite doespre-bundles once, with esbuild serves on demand, unbundled
When that cost is paidon installper file, per request

The consequence is the whole point. Starting the dev server no longer means building the app — dependencies are already prepared, and your source is not built at all until the browser asks for a specific file. Start-up stops scaling with the size of your codebase.

Saving a file re-transforms that one file and hands the module to HMR, which swaps the module in the running page. Not a rebuild, not a reload.

Production still bundles, with Rollup. Hundreds of separate module requests are fine over localhost and bad over a network, and a real build wants minification, tree-shaking and chunking. Dev and production are deliberately different mechanisms.

If it helps — against Gradle

AddedMy analogy, not Vite's.

An Android build assembles everything into an APK before the emulator sees any of it, and incremental builds shrink that work without removing the packaging step. Vite's dev mode removes the packaging step entirely: the browser loads your source files directly and only the file you touched is re-processed.

Roughly, Vite's dev mode is what Live Edit is reaching for, except unbundled serving is the normal path rather than a special case.

The honest summary. Vite's technical claim is the dev feedback loop. Its stronger claim is that everyone consolidated on it — Nuxt, SvelteKit, Astro, React Router, SolidStart, Vitest, Storybook, Laravel and Rails all build on it, so it is where the integration work already exists. Picking Vite is mostly picking the default.

The two-tool problem, and Rolldown

Using esbuild for dev and Rollup for production means two transformation pipelines and two plugin systems, held together by glue. Things behave differently in dev than in production, which is the worst class of bug to chase.

Rolldown is a single bundler, written in Rust, using Oxc for parsing, transforming and minifying. Rolldown is meant to do both jobs, keep Rollup's plugin API so the ecosystem survives the move, and remove the dev-versus-production gap.
